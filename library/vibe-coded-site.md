# Vibe-coded site, without the AI look

Source: @thedesignshop.tds. Four steps for a site that was built in a vibe-coding tool and still looks generic.

Use this file when the work is planning, building, or polishing that kind of site. Open it from `C:\Users\ANISH\Documents\ai-playbook\LIBRARY.md` and use only the step the task needs. Places to study real interfaces stay in the vibecoder design sites file.

1. Plan in the vibe-coding tool before building. Say what is required, the look and feel, some references, and the niche of the site.
2. Build one section at a time. Fix the UI and UX of that section, then move to the next.
3. For interactive elements and animation, do not only tell the tool what to do. Copy an existing prompt, paste it, and describe how that piece should look and work.
4. The result the post is aiming at: a site that stands out from the generic crowd and is memorable to use.
